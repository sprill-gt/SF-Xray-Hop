# 单机与双机连接指南

当前交付范围为一个入口对接一个出口。多个入口复用同一出口链接时共享 Relay UUID；“登记入口”仅记录显示名称，不能单独撤销其中一个入口。逐入口授权管理尚未实现。

先完成任一台安装，即可使用本机直连。默认名称 `node-短ID`，不根据 IP、主机名或供应商猜测用途；菜单5可修改名称。

## 从出口 B 开始

在出口运行 `sudo sfxh`，选择 **1 链式引导 → 2 出口 B**。检查本机直出通过后，显示“出口已配置，等待 A 对接”。选择 **1 显示对接链接**，复制完整一行；这是交给 A 的连接凭据。可以选择 **2** 登记 A 的 IP／域名和名称，回车跳过。该登记不是已连接的证据。

切换到入口 A 的 SSH 窗口：安装后 `sfxh → 1 → 1 入口 A → 1 已有链接`，粘贴 B 的对接链接。核对不含密钥的地址、端口、协议及 RTT 摘要，确认本地下游名称。独立下游及完整路径测试成功后，再确认切换并复测正式服务。

## 从入口 A 开始

入口 `sfxh → 1 → 1 入口 A`，选择 **2 尚未准备** 查看出口操作步骤。向导复用已验证发行来源，离线安装则提示复制同一完整发行包。保留 A 窗口，切换到 B 完成上段准备，再回 A 粘贴。

编号仅是当前流程展示；节点没有不同的协议类型，也无需服务器间 SSH 信任。

## 设备日常使用

入口侧完成后选择 **1 显示链式链接**，或主菜单 **4**，导入手机／电脑。主菜单 **3** 的直连链接作为应急线路。链接备注分别为 `链式 | A名称→本地下游名称`、`直连 | 本机名称`；B 对接链接为 `对接 | B名称`。

出口 B 的主菜单4不会提供自己的 Relay 冒充设备双跳，而会指向用户登记的 A 或提示未登记。单机主菜单4提示链式未开启。导出完整客户端 JSON 可使用 `sfxh view json relay`（仅A）或 `sfxh view json direct`。

本机协议测试不能证明设备从公网可达；最终仍需独立设备验证出口。出口窗口没有 A 侧证据时一直保持“等待 A 对接”的表述。

## 更换、取消及恢复

入口主菜单 **1 → 2 更换出口**，粘贴新的 B2 对接链接。失败保留旧出口；成功保持 A 的 UUID、密钥、SNI、端口、路径等连接参数。新导出备注反映 B2，旧客户端备注不会自动更新。

入口主菜单 **1 → 3 取消链式**，明确确认后 Relay 恢复 A 本机出口。下游离线不会自动执行这一操作。改用途为单机／出口也会说明同样影响并要求确认。

向导0返回会保存用途与步骤；SSH中断后再进入可继续，候选必须重测。再次进入已有链式直接管理当前连接，不覆盖下游或重新生成身份。菜单5中的名称、下游别名、登记入口都是本地展示信息，不重启正在运行的代理。
