# v0.1.3 审查处理记录

核对日期：2026-09-30。输入为用户提供的 `SF-Xray-Hop-v0.1.3-audit.md`，基线 `ce94e8dc3d5347977395ab87ec0bcd2273fcaad3`。本文是维护者逐项核对后的处理记录，不将审查中的建议或历史测试当成新一轮实机验收。

## 判断

主要结论成立：应补强更新与检测边界，保留现有协议和统一节点模型。未发现理由改动 XHTTP auto、默认 Chrome、双身份路由或默认拒绝策略。

归档半成品与未校验 Relay 出口是实现缺口；临时 Xray 以 root 运行是权限边界问题，不能写成已经发生入侵。现有 Relay 路由没有故障直出的实现，缺少自动出口比对也不等于已证明泄漏。核心包散列正确同样不能证明浮动 main 管理脚本绑定审查版本。

## 已落实的处理

| 审查项 | 实现与限制 |
|---|---|
| P1-01 核心归档中断 | 每归档锁、唯一 staging、完整性及同步后原子发布；未引用损坏档隔离重建，被引用档保留并拒绝覆盖。SIGKILL 恢复不等于断电持久性已验收。 |
| P1-02 安装来源 | 一行命令绑定完整提交与预先给定的源码包 SHA256；摘要、结构、管理器版本均通过后执行；保存 source.json，跨机向导复用同版本。没有独立签名信任根，不声称抵御首次发布渠道失陷。 |
| P1-03 临时进程权限 | 候选服务端、客户端、TLS ping、测速客户端均由有时限的 DynamicUser 单元运行，无有效 capabilities；凭据通过 LoadCredential 私密传递，结束时清理控制组。 |
| P1-04 出口正确性 | 独立下游基准与完整 Relay 路径在同一检测站、同一地址族比较至多3个样本，不能确认就停止提交；保留动态 NAT、双栈及共同出口的证据限制。 |
| P2-01 无谓重启 | 比较规范化 config 和 binary SHA256；元数据单独提交、不重启，旧健康时间不刷新；完全一致直接返回。服务停止时不跳过恢复安装。 |
| P2-02 测速误判 | 明确本机自检；整机／服务 CPU 与 steal 分开，阶段均值／峰值分开；下载有效部分传输保留，上传未确认单独标记，HTTP200错误页拒绝。 |
| P2-03 长期运维 | 下载空间检查、引用保护的历史清理、显式离线核心恢复；管理器升级发布完整版本并原子切换入口，仅接受 config／unit 均兼容的更新，不做自动 schema 迁移。 |

RTT 提示也明确：修改本机保留密钥，但另一台已保存的客户端偏好不会自动同步。既有客户端是否继续认证与完整采用新偏好分别描述。

## 验证方式

审查附带报告提及的复现 JSON 未随文件提供，本次重新编写独立夹具验证。所有新测试源文件进入仓库，生成凭据及原始日志只在忽略的测试目录中。

- `tests/archive.sh`：创建、写 binary、写 metadata、发布后各阶段 SIGKILL；修复未引用残留、拒绝替换引用档、并发发布。
- `tests/transactions.sh`：原事务故障注入，以及元数据免重启、相同配置不提交、停止服务恢复、离线恢复不推进 last-good／不联网、拒绝离线改路由。
- `tests/prune.sh`：活动、last-good、事务、历史备份引用及至少5个已验证核心保护。
- `tests/bootstrap.py`：隔离下载替身，覆盖 TTY、篡改、版本不符、未固定版本、包路径攻击和显式升级。
- `tests/manager.sh`：普通文件旧入口迁移、入口切换前被杀、旧版保留、不重启、不兼容 unit/config 拒绝。
- `tests/probe-privileges.sh`：真实 systemd 检查 UID、有效能力、凭据不可被 nobody 读取、停止与到期清理。
- `tests/health-live.sh`：生成临时身份，使用默认 REALITY 目标、真实降权核心与少量公网 HTTPS 请求，检查单节点及回环双跳出口比较。不读取正式节点凭据，不更改正式服务。
- `tests/exits.sh`、`tests/reporting.sh`：出口不符、地址族／站点不可比、NAT 样本重合及测速分类／资源口径。

在 Ubuntu22.04 的 jq1.6 验证时另发现，带可选转换的更新赋值会丢失 HTTP 字段；已改为普通赋值，保持 jq1.6／1.7 兼容。

最终执行结果见[测试记录](testing.md)。两台机器本轮已被用户重新安装，所有故障注入都在隔离目录执行；正式服务未升级、未重启。本版代码修改不能计为新的生产部署通过。

## 仍未完成的验收

Debian12/13 部署与3×3矩阵、真实整机重启／断电、新版在不同实际出口的双 VPS 更新和真实第三台 B2 替换、手机／GUI 客户端、长期连接与1C1G容量测试仍待验证。管理器备份有人工恢复材料，但尚无独立自动回滚命令。签名信任根不在本轮伪装成已完成；没有因为新增检测而把未知出口当成成功。
