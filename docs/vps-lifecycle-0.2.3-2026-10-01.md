## 证据边界

设备请求从独立 Windows 机器发出；服务器只进行安装自检、协议健康检查及小请求出口基准，不运行吞吐压力测试。出口按同一 HTTPS 站点、IPv4、相近时间比较；不以地理位置、延迟或一次 TCP 连接作为双跳证明。

原生核心 JSON 请求不等于 v2rayN 7.25.2 或 v2rayNG 2.3.8 的 GUI 导入／重连验收。Debian 12／13、第三台独立出口 B2、真实断电、长期负载趋势仍需各自证据；历史 unsafe 核心不存在时，不伪造 verified 归档来声称完成真实历史回滚拒绝。

## 干净安装缺陷与处理

公开引导脚本使用 `umask 077` 和 `tar --no-same-permissions`，安装前的源码目录不可被其他用户遍历，探测worker为0700、目标列表为0600。0.2.3直接把这两份源文件只读绑定到DynamicUser隔离单元，文件模式随绑定保留；实际错误为 `/usr/bin/bash: /tmp/sfxh-safety-worker.sh: Permission denied`，退出126。不是26.9.30缺少防护，也不是网络质量问题。

用原公开包按相同权限解包后独立复现；普通模式解包的同一代码／核心通过，解释了此前隔离源码检查为何未覆盖此安装路径。0.2.3干净安装不能记为通过；没有覆盖或移动原发行资产。

诺亚恢复原私密备份后保持出口用途。Windows沿原VMISS → 诺亚请求，首次得到curl35，第二次通过；没有为让结果好看而删除失败，也没有重启VMISS。仅此两次请求不代表长期恢复可靠性。

修正版本为0.2.4：在0700临时父目录内，用显式0644副本准备不含凭据的worker和目标列表，再只读绑定进隔离单元。源文件权限、私密材料、DynamicUser、PrivateNetwork、能力限制和阻断判定保持。新增真实systemd回归使用0600源文件，验证探测成功且源文件仍不可被其他用户读取；旧核心仍需拒绝。

0.2.3候选停止晋级，剩余生命周期改用0.2.4独立记录，不继承旧包的未完成结论。
