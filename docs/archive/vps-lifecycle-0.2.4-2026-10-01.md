## 设备与链路验收

使用独立Windows的官方Xray26.9.9执行导出的客户端JSON。本机HTTP代理仅绑定127.0.0.1；每次正向测试包含3个同端点IPv4出口样本和1次额外HTTPS请求。基准由对应VPS在相近时间请求同一站点取得。日志和真实凭据仅保存在私有测试目录。

Windows实际二进制输出为 `26.9.9 / 52a412d / windows/amd64`，SHA256为 `0d0fc0ea2b05641acb78c01fc36ad694e7b029861b2d5eb93da0e3e9fda9a98f`，没有借用GUI的版本标签代替实际运行核心身份。

两台各执行 `core update --version 26.3.27 --yes`，确认在安全门槛失败，state/config及正式进程保持，核心未发布到归档。随后在线应用26.9.9并验证实际双跳，恢复pre，再回滚到这份实际成功使用过的26.9.9归档。offline测试前移走该二进制的检查缓存，确认再次运行真实隔离检查，状态先记为 `unverified-offline`；Windows请求和后续doctor是另外的在线证据。最后两台恢复pre／26.9.30，当前下游与连接材料保持。

| 场景 | 结果 |
|---|---|
| VMISS Direct → VMISS出口，Relay → 诺亚出口 | 通过；另从Windows验证诺亚Direct基准 |
| 不可达候选替换失败，旧配置和真实进程保持 | 通过，拒绝后原链式HTTPS通过 |
| 同一诺亚出口重新导入替换，入口凭据保持 | 通过；不等于独立第三台B2验收 |
| 主动取消后已有Relay从VMISS出口，重新建立后回到诺亚 | 通过，沿用同一Windows客户端JSON核对两个出口 |
| 停止诺亚时Relay失败，VMISS Direct继续可用 | 通过，未自动从VMISS直出 |
| 恢复出口后再次连接 | 首批curl35失败，第二批通过；入口配置及真实进程未变 |

出口停止测试从发起 `systemctl start` 到完成第二批通过请求约23.954秒，包含SSH调用、失败尝试、重试等待和4个HTTPS请求；这是验收用时，不是精确中断时长、TCP延迟或GUI恢复时间。

整机恢复通过真实运行的RTT修改事务触发：在新代次已激活且尚未提交时终止该命令的独立进程组，保留真实事务记录，再执行整机重启。恢复要求boot ID确实改变、服务active/enabled、事务文件消失、原state/config逐字节摘要恢复、SSH配置摘要保持，随后由Windows复测。没有用手工编造的事务文件替代中断，也没有把正常重启称为断电测试。

从重启命令返回到观测满足上述恢复条件：诺亚约60.248秒，VMISS约27.695秒，包含SSH重试与轮询间隔，不是内核启动耗时或精确业务中断时长。诺亚重启后的首批链式请求失败，下一批通过；VMISS重启后的Direct与Relay批次直接通过。

0.2.4阶段共保留5批正向HTTPS测试的curl35失败：诺亚的三次核心切换后各一批、出口停启后一次、整机重启后一次。每次后续重试通过且未手工重启VMISS；0.2.3失败恢复阶段另有一批同类失败。测试器没有记录失败请求在批内的序号，因此只能确认“首批失败”，不能把它精确写成第一个请求，也不能由此确定底层TLS／会话缓存原因。没有把这些失败删除后统计成零失败或无缝切换；实际GUI的自动重连仍需验证。

## 收尾及边界

最终两台保持0.2.4管理器、实际运行核心26.9.30、pre频道、443、0-RTT、Chrome、XHTTP auto和archive.archlinux.org，单公网inbound与两个独立身份。对照实际配置核对了按email路由；两个节点各自最终的unit、权限和doctor九项全部通过。Windows最终VMISS Direct、VMISS Relay和诺亚Direct三批请求均通过。

测试临时目录已从两台删除，没有待恢复事务或残留探测单元；SSH配置摘要保持且SSH/Xray服务正常。卸载时对照原基线检查其他运行服务均保留。原私密备份及新客户端材料保留在Windows受限目录，未进入Git。完整卸载重装已生成新凭据，应在VMISS执行 `sfxh view relay` 取得日常链接，`sfxh view direct` 取得应急链接。“保持入口链接”仅用于同次安装内改名、核心切换和下游设置／取消，不适用于完整卸载重装。

未执行的项目继续明确保留：v2rayN7.25.2与v2rayNG2.3.8实际GUI长URI／JSON导入、常驻客户端会话重连、长期日常负载趋势、Debian12／13、第三台独立出口B2、真实断电。没有真实旧版不安全历史归档时，不伪造verified元数据；普通候选拒绝、隔离负向测试和真实历史offline回滚分别记录。新版本继续为暂时性实验产物。
