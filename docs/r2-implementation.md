# R2 产品交互实施记录

依据用户提供的 `SF-Xray-Hop-v1-product-interaction-spec-r2.md`（2026-09-30）实施。它是产品目标，不代表已完成实机验收。本项目继续标为暂时性实验产物。

## 实施边界

- 单机先可用：443、0-RTT、Chrome、XHTTP auto、`archive.archlinux.org`；首次名称来自稳定节点 ID。默认只显示直连链接，链式按需开启。
- 统一主菜单：链式引导、核心管理、直连分享、链式分享、节点设置、SNI、RTT、脚本更新、完整卸载。
- 单机／入口／出口是本地展示上下文；入口必须有成功提交的下游，出口没有下游。下游故障不会自动直出。
- 名称、下游别名、用户登记的入口地址独立于身份、密钥及路由标签。角色或取消链式导致路径变化时明确确认。
- 核心 pre/stable/pinned 与脚本版本独立管理；pre 只选择实际 prerelease，分页后按数字版本比较。脚本默认选择项目正式 Release，无可用版本则明确报告。
- 脚本升级验证完整发行包后原子切换目录，保留可回退版本；回退检查当前状态，不恢复过时的下游和凭据。
- 完整卸载使用明确确认词和项目所有权边界，不能删除他人服务、共享依赖、SSH 或远端副本。

## 状态与兼容

R2 使用状态 schema 2 增加 `presentation`；旧 schema 1 可读，在下一次管理变更时复制转换。转换保留现有名称、身份、RTT、SNI、频道和下游。已配置下游推导为入口；没有出口用途证据的旧节点不自动标成出口。旧脚本不能读取新状态时，拒绝回滚，不把历史私密状态覆盖回来。

## 验收记录

v0.2.0 已实现上述交互、schema2 展示信息、分页频道选择、独立脚本更新／回滚以及默认完整卸载。新增测试使用真实官方26.9.9核心校验配置；下载、安装、事务服务操作和卸载使用隔离替身。两台Ubuntu分别完成验证，详细逐项记录见[验收记录](testing.md#v020-r2-实现回归2026-09-30)。

初始隔离回归中，Windows回环真实核心26项通过；Ubuntu22.04和24.04.3各完成真实受限临时单元、TLS目标、HTTPS及回环链式出口比较。当时正式xray.service的PID及启动时间保持不变。之后用户授权实际部署，已执行升级、卸载、全新安装、真实双跳及核心回滚，见独立的[R2实机记录](vps-r2-2026-09-30.md)。

正式验收仍待Debian12/13部署、三系统3×3真实双跳、独立GUI客户端、真正断电、外部持续负载和长期稳定性。性能按实际使用方向和独立设备记录，不把标称200 Mbps作为每次测速必须达到的数值。0.2.1修正实测发现的运行版本读取SIGPIPE；后续0.2.2仍以实验Release提供，默认正式发行入口不自动选择实验版本。各阶段已测／待测状态以实机记录为准。

代码目录切换不自动做运行配置／unit迁移；旧脚本不能读取当前状态时拒绝回滚。只有纯展示信息采用metadata事务，即使服务停止也不会因改名而启动服务。正式发行前仍需完成以上验收。

0.2.2统一数字菜单与CLI的测速预算提示，按当前端点上限计算，不改变协议或测速载荷。固定VMISS中转、诺亚落地后的失败保留、核心频道及脚本升级证据另见[固定方向验收](vps-forward-2026-09-30.md)。0.2.1及更早版本的实测保留历史边界，不视为本版重新执行全部测试。

## 协议及发行来源

- [Xray VLESS outbound](https://xtls.github.io/config/outbounds/vless.html)：客户端 RTT 与服务端票据寿命分别设置。
- [Xray VLESS inbound](https://xtls.github.io/config/inbounds/vless.html)：服务端 decryption 参数。
- [v26.9.9 encryption 实现](https://github.com/XTLS/Xray-core/tree/v26.9.9/proxy/vless/encryption)：已验证基线，不是永久默认更新版本。
- [GitHub Releases API](https://docs.github.com/en/rest/releases/releases)：分页、draft/prerelease 标记及资产 digest；`latest` 不等于数值最大的版本。

以上来源核对于 2026-09-30。HTTPS 同源摘要可检测内容不一致，不宣称独立签名或供应链真实性证明。
