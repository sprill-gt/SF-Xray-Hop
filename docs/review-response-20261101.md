# v1.1.0 投产前审查复核

日期：2026-11-01。依据：提交 97f8cef 的源码、测试与用户提供的静态审查报告。本记录区分代码事实、策略边界和缺少实测的事项；没有重新查询线上 CI、Release 或生产主机。

原报告不能直接作为无条件投产批准：它明确没有运行测试，部分模块未审阅，且列出了未关闭的服务启动和重启持久化风险。也不能因此把所有列项都当成必须修改的缺陷。

| 项目 | 复核结论与处理 |
| --- | --- |
| 1 动态出口 | sf_exit_compare 确实要求实际样本为独立基准样本的子集，这是严格确认策略。动态出口可能失败，但不能推断所有 WARP 部署、每次变更必然失败；metadata 改动不走运行时探测，显式 offline 恢复也不做在线出口确认。保留严格策略；仅检查“不同于入口”不能证明经过指定下游，不采用该建议。 |
| 2 BBR 覆盖 | 持久化冲突是有效风险，当前运行值不能证明重启后的值。本次 status 增加运行值偏离提示和持久化未验证提示；接管已有 BBR 时说明 off 恢复的是接管时原值。尚未实现完整的启动加载顺序冲突分析。不得把 sysctl --system 当作只读检测，它会应用主机上的其他 sysctl 设置。报告所述生产主机手工文件未重新核实，不执行删除。 |
| 3 容器 | 当前检查 systemd 可用性，随后仍需通过实际安全探测。容器类型不能单独证明特定安全能力是否可用，不增加一刀切拒绝策略。错误信息可进一步改善。 |
| 4 unit 延迟生效 | 有效风险：成功的脚本更新删除 unit 备份，之后配置事务只回退代次，不能恢复旧 unit。保持脚本更新不重启服务的约定；本次没有实现跨后续事务的 unit 恢复，不标记已解决。升级旧 unit 的节点仍需维护窗口验收。 |
| 5 跨系统实测 | 属于验证缺口；Debian 容器测试不能代替该系统上完整 systemd 生命周期验收。本次没有新增实机证据。 |
| 6 撤回清单 | 静态策略的更新边界成立。保留现有机制。本次另修复发现的问题：自动选版原来会把策略读取错误也当成跳过候选；现在策略错误直接停止。 |
| 7 更新提醒 | 手动更新是既有设计；没有自动创建定时任务或改动主机。 |
| 8 选版提示 | 已修复：自动选版用“跳过已撤回版本，继续查找”；明确指定撤回版本仍拒绝执行。 |
| 9 GitHub 限额 | 有限额和网络失败分支，具体页数随标签数量变化；本次不宣称已重新验证在线 API。 |
| 10 unlock | 子 shell 退出关闭锁文件描述符，不构成已证实的锁泄漏，无需为了显式 unlock 修改退出路径。 |
| 11 脱敏 | 属于隐私与排障信息的取舍；保留现有脱敏策略。 |
| 12 发行说明 | 已修复：按 tag 查找对应 docs/releases/<版本>.md 并附入说明，文件不存在时保留 CHANGELOG 指引，不再固定引用 1.1.0。 |

本轮审查修复整理为 1.1.2 正式版候选；不部署、不删除生产配置，已发行的 v1.1.0 资产保持。版本发行状态以 GitHub Release 为准。

验证：本地 Git Bash 下 tests/releases-auto.sh、tests/bbr.sh 通过（网络、服务和 sysctl 使用隔离夹具）；改动的 Shell 文件通过 ShellCheck。tests/check.py、tests/privacy.py 和 git diff --check 通过。这些结果不等于 Linux 实机、重启持久化或公开发行验收。
