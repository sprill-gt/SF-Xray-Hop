# v0.2.6 RC：日常试用交付

记录日期：2026-10-01（UTC+8）。用户确认将日常使用验收接手，停止追加重复故障测试，并要求发布 RC、增加清晰的当前脚本版本入口。

## 本次变化

- 新增 `sfxh version`／`sf-xray-hop version`，直接显示当前管理脚本版本，无需 sudo、jq 或联网。
- 保留 `sfxh --version` 的纯版本号输出，供自动化和管理器更新校验使用。
- 主菜单、`status` 及脚本更新页明确显示“脚本版本”，与 Xray 运行／配置核心版本区分。
- 一键安装及升级文档指向 v0.2.6，完整收录上一轮 Debian 13 验收、失败和暂停记录。

本次不改变节点身份、协议、下游路由、事务、安全门槛或核心选择。支持范围继续仅声明 **Debian 13 和 Ubuntu 24.04.3 LTS，amd64**。双机用途固定为设备 → VMISS 中转／入口 → 诺亚落地／出口 → Internet。

## 证据和状态

服务端基线来自 [v0.2.5 Debian 13 双机生命周期](vps-lifecycle-0.2.5-2026-10-01.md)：全新安装、卸载重装、管理器／核心更新回滚、身份路由、错误候选保留、出口故障不直出，以及事务中断后的整机重启恢复均通过。Ubuntu 24.04.3 的实机证据来自 0.2.4。不能将这些版本的运行结果表述为 0.2.6 已重新部署或重跑全套验收。

实际 v2rayN 7.25.2 的两条长 URI 导入及字段保留通过；实际 GUI 连接、JSON、Android 和长期体验交给用户。持续测试被暂停，不能宣称完成十分钟、空闲恢复或长期资源趋势。0.2.6 只需完成版本入口、源码／文档和发行包检查，以及现有 CI 回归，不再次操作 VPS 做破坏性验收。

## 发布及转正

GitHub 发行名称为 **SF-Xray-Hop v0.2.6 RC**，标签保持工具链支持的 `v0.2.6`，标记 Pre-release。RC 是可交付日常试用的发布候选，用户确认日常连接、速度、重连和常用应用没有阻塞性问题后再转正式版；没有额外硬性观察时长。

维护重启／换核中断现有连接、短暂请求失败后自动恢复，是当前明确记录的行为，不单独卡住转正。持续断流、配置丢失、出口错误、无法恢复的更新属于需要处理的阻塞问题。不会承诺应用自动重放失败请求或所有设备无中断。

已有安装升级管理器：

```bash
sudo sfxh self update --version 0.2.6 --allow-pre
sfxh version
```

脚本升级不更换核心或节点凭据。默认更新仍仅选择项目正式发行；RC 必须明确指定版本与 `--allow-pre`。首次安装使用[根 README](../README.md)的固定摘要一键命令。发布资产中的 `manifest.json` 记录完整源码提交、包大小与 SHA256；已发布标签和资产不覆盖。
