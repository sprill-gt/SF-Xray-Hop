# 运维指南

## 更新与恢复

pre 仅选择非草稿的实际预发布，stable 仅选择正式发布；两者均分页读取后按数字版本选择，pinned 固定版本。用户手动更新；核心下载核对官方资产摘要和 dgst 校验，至少保留五个验证成功的核心。散列校验不等同于独立发布签名。

0.2.3起，能力检查还包括认证后私网目标的隔离行为检查。已实测26.9.9和现用26.9.30通过，26.3.27因不能保持这项防护而被拒绝；不是按版本数字猜测安全性。新核心、历史回滚和doctor共用门槛；精确二进制SHA256与当前检查代码／模板内容匹配时可复用本地证据。首次检查约40秒，无公网请求；PrivateNetwork、IPv6或临时服务不可用时也会停止，不能只靠连接超时判为防护有效。范围与限制见[审查记录](audit-0.2.2.md)。

提交成功后清理历史，也可执行 `sudo sfxh core prune`：保护活动、last-good、未完成事务代次，另保留最近10个代次、5个备份和最近5个验证成功的核心。任何保留代次／备份或运行引用都会保护相应核心，因此可能多于5个。未引用候选、残留 staging 和隔离目录还保留至少一天，避免与下载并发冲突。没有五次成功记录时不会伪造五个版本；下载未通过能力或链路验证的核心不进入回滚列表。下载前检查所需文件系统至少有512 MiB空间。

归档发布采用同文件系统 staging、完整性校验、同步及原子改名。遇到缺失 metadata 等半成品，只有未被任何保留代次、备份或运行核心引用才隔离重建；被引用的损坏核心保留现场并报错，不自动删除。进程中断后的重试已隔离验证，真实断电持久性尚待验收。

更新失败恢复旧 core、配置、状态并复测。手动回滚使用历史核心测试当前配置，不偷偷恢复旧下游。断电／进程中断由启动恢复逻辑处理。检测到配置被外部修改时停止写入。

可用 `sfxh core rollback` 数字选择历史归档，或者指定完整归档 ID。回滚成功后进入 pinned，后续更新需显式选择频道。`sfxh core update --channel stable` 会验证并切换稳定频道。更新器不会无人值守自动运行。

网络故障时可明确执行 `sudo sfxh core rollback <完整归档ID> --offline`。只允许换成已验证历史核心并使用**当前配置**，检查摘要、隔离安全行为、配置、服务和监听，不运行公网探测，也不推进 last-good。历史verified标记不能代替本版安全检查。status 显示“离线恢复，出口未验证”；网络恢复后运行 doctor。默认回滚仍要求网络复测，不会悄悄降级为离线成功。

## 管理脚本升级

菜单8或 `sfxh self check/update/rollback`；脚本与核心分别更新。默认选择项目正式 Release；没有正式版就停止。维护者测试可明确 `--version 0.2.3 --allow-pre`；只有相应 Release 及完整资产实际发布后才可下载。脚本更新不替换正在运行的核心；之后运行doctor检查当前核心安全行为，失败时需选择通过门槛的核心。回滚到旧管理脚本也会回退管理侧校验逻辑，应谨慎使用，不能当作安全补丁仍然生效。

发行包契约：Release 包含 `manifest.json` 和 `SF-Xray-Hop-版本.tar.gz`。清单 schemaVersion=1，project=SF-Xray-Hop，包含 version、40位 commit、archive.name/sha256/size；标签解析到的提交必须匹配。API资产摘要（若提供）和完整包摘要均检查。HTTPS同源摘要不是独立签名，项目没有把包内公钥作为信任根。

验证包后检查当前状态、核心、unit及配置兼容；当前实现不自动迁移 unit 或运行配置。完整代码发布到 `releases/版本-内容摘要/`，一次原子改名切换入口，后续命令加载同一目录中的模块。后置检查失败恢复旧脚本；中断日志在下一次修改时恢复，提示重开命令。脚本操作不重启正式核心。

`self rollback` 检查旧脚本能否读取**当前**状态；旧版不支持schema2时拒绝，不恢复历史下游或密钥。保留当前、上一可回退版本及最多一个其他历史版本。事务未结束不清理历史。普通重复安装保留当前脚本与节点，核心更新不更换脚本。

旧版0.1.3安装没有记录服务用户UID。升级脚本不会补造历史所有权；这类安装完整卸载时可能保留专用用户并返回非零状态，新安装会拒绝接管遗留用户。需要管理员核对其确属旧安装且没有其他进程使用，再清理账户。新安装会写入UID所有权记录；实测兼容边界见[R2部署记录](vps-r2-2026-09-30.md)。

安装器无源码参数时选择正式Release；`--script-version 版本 --allow-pre-script` 明确选择实验发行。维护者还可固定 `--source-commit 完整SHA --source-sha256 源码包摘要`。离线完整包运行 `sudo bash install.sh`，已有安装离线更新用 `sudo bash install.sh --upgrade-manager`。这些入口均复用完整目录切换，不直接覆盖零散模块。

## 修改连接参数

本机 RTT 与 `rtt downstream 0|1` 分开；下游0-RTT是否实际恢复由B决定。RTT 保留密钥，重新导入才能完整采用新的客户端偏好；本机修改不会同步改写另一台保存的参数。target 修改可能改变 SNI，需要更新设备或上游节点链接；修改前显示影响。fingerprint 只改变本节点导出客户端配置，不覆盖导入下游的参数。名称、导出指纹和实际 core/config 不变的频道设置不会重启；完全相同的设置不创建新代次。纯显示修改保留服务停止状态；显式运行配置变更或安装恢复才走启动验证。

## 检测指标

status 读取服务状态与带时间戳缓存，不测速。doctor 分别检查 binary、systemd、配置、监听、两个身份、target、DNS、HTTPS 和出口。本机成功不证明公网防火墙或设备成功。

TCP 连接耗时、ICMP RTT／丢包、HTTPS 成功率分开命名。ICMP 全部无应答时无法区分禁 ping 与丢包，显示未采集。观察出口不直接用服务器地址代替。没有 B 管理权限时不报告 B CPU 或 RAM。

有下游时，先独立访问下游获得出口基准，再与完整 Relay 路径比较；无下游时用 Direct 作基准。同一次检查固定出口检测站与地址族，各取至多3个短时样本。Relay全部观测地址必须属于基准集合才确认；混入预期之外的地址即为unconfirmed，完全不相交为mismatch，两者都阻止提交。样本须带UTC时间，距现在不超过600秒、最多领先30秒，两组相隔不超过300秒；缺失、过期、族或端点不同均未确认。不自动回落本机。动态NAT可能超出短时基准，不能据此断言泄漏；短样本确认也不是全流量不泄漏证明。A/B共用公网出口时仍无法辨别拓扑。HTTP失败和HTTPS超时保留独立诊断。

## 性能

`test --performance` 默认 Relay，可选 Direct，明确标为**本机自检负载**：额外探测客户端也消耗本机 CPU，不能直接认定正式服务已经耗尽1C1G性能。100／150／200 Mbps，每方向每级最多8秒。按阶段记录整机忙碌 CPU、steal、正式服务 cgroup CPU 均值／峰值及服务 RSS。cgroup 不可用时显示 `—`；CPU 服务口径为一个逻辑 CPU=100%，RSS 为进程之和（共享页可能重复），峰值来自约1秒采样。阶段达到限速不代表极限吞吐。

每级以6秒目标速率计算载荷，再按 `data/probes.json` 的端点上限裁剪下载量。2026-09-30 实测默认端点拒绝大于等于100,000,000字节的请求（HTTP403），因此下载上限为99,999,999字节，不能将请求拒绝当成带宽不足。六阶段正常端点载荷约612.5 MB；8秒超时及限速对应预算约900 MB。高速档可能提前完成，报告实际时长，不称为跑满8秒。协议、预检、curl限速采样误差和中转重复计费流量另计，不作为云账单硬上限。可用内存低于64 MiB、取消或临时客户端到期时停止压力。

完整成功必须满足约定字节及端点响应：下载检查长度和二进制类型，上传要求服务端确认收到字节。错误页面即使 HTTP200 也不算测速成功。下载超时但收到有效部分数据时保留观测吞吐；上传超时保留“客户端送出、服务端未确认”的观测量，不算有效验收。吞吐时间含建连；不再根据单次 CPU 峰值建议升级，正式容量应从独立设备持续测量。

外部性能复测应先固定用户实际使用的入口、出口和方向，再核对最终出口。不得为了测试调换用途，或将反向链路、本机额外客户端的结果与设备实际速度混为一谈。测试客户端放在独立设备上，两台 VPS 仅运行正式代理；记录测试源、字节量、时长、连接数及 MB/s／Mbps 单位。标称200 Mbps不意味着每个测试源、每次短样本都应跑满；低于标称值本身不证明脚本或协议故障。

初始适配 [Cloudflare 官方测速接口](https://github.com/cloudflare/speedtest)，端点失败独立报告，不自动认定代理失败。不在打开菜单时运行压力测试。

自0.2.2起，数字菜单与CLI共用按当前端点数据计算的流量提示，避免菜单保留旧载荷数值；这项修正不改变测速请求或实际传输参数。

## 日志和卸载

完整凭据在主动 view／导出及首次交互安装成功时显示。自动输出统一脱敏，配置验证 stderr 同样按敏感输出处理。日志有限额和轮换。默认完整卸载删除私密备份；仅显式 --keep-data 才保留。只删除本项目拥有的服务和路径，不移除共享依赖。

管理日志在 `/var/log/sf-xray-hop/manager/manager.log`，核心日志在 `core/core.log`，正常输出以1 MiB阈值轮换。`sfxh logs` 只显示最新片段，再次脱敏。原始生成参数属于0600临时凭据文件，不作为运行日志公开。

完整卸载使用 `sudo sfxh uninstall` 或主菜单9，输入 `UNINSTALL` 确认；空输入、EOF或其他文字取消。非交互必须 `--yes`。先校验项目目录、服务和入口所有权，再停服务并删除私密配置、核心、完整脚本版本树、备份、缓存、日志及有归属记录的临时探测单元。专用用户归属或空闲状态无法确认时保留并报告。

不会删除其他服务、共享依赖、SSH、云防火墙、远端配置或客户端已导入副本。自行克隆的开发目录不属于安装资产。文件删除不等于存储介质安全擦除。

显式 `--keep-data` 会保留脚本及配置以供恢复；再次安装可复用身份和下游。默认完整卸载后则无法恢复已删除凭据，原链接失效。
